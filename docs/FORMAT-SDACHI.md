## Рекомендуемая структура итогового отчёта

Netology требует: *«процесс задокументирован, аналитика выбора инструментов, зоны роста»*.

### Титул
- Дипломная работа, трек DevSecOps
- ФИО, группа, дата
- Объект: Necommerce
- Эксперт: Нияз Кашапов

### 1. Введение
- Цель: построить безопасный CI/CD-пайплайн
- Объект: Necommerce (Kotlin + React + Docker)
- Платформа: GitHub Actions, GHCR, VPS
- Ссылка на репозиторий

### 2. Выбор инструментов (аналитика)
| Задача | Инструмент | Почему выбран | Альтернативы |
|--------|------------|---------------|--------------|
| CI/CD | GitHub Actions | бесплатно, интеграция с GitHub | GitLab CI |
| SAST | Semgrep | правила p/ci, JSON в CI | SonarQube |
| DAST | OWASP ZAP | стандарт OWASP, baseline в CI | Burp |
| Секреты | Gitleaks | простой, для git | truffleHog |
| SCA/образы | Trivy | deps + Docker | Snyk |
| Registry | GHCR | рядом с кодом | Docker Hub |

### 3. Архитектура пайплайна
- Схема (можно из `DIPLOM.md` / draw.io)
- Описание workflow-файлов
- Триггеры: push, pull_request

### 4. Этап 1 — CI/CD
- Сборка Docker, push в GHCR
- Деплой на VPS (когда будет)
- **Скрины:** Actions, Packages, VPS

### 5. Этап 2 — SAST
- Semgrep backend + frontend
- **Артефакты:** semgrep-*.json
- Примеры находок + интерпретация

### 6. Этап 3 — DAST
- OWASP ZAP
- **Артефакты:** zap-report.html

### 7. Этап 4 — Security Checks
- Gitleaks, Trivy, npm audit

### 8. Этап 5 — Security Gateway
- Политика блокировки
- Скрин PR с комментарием

### 9. Зоны роста
- Defect Dojo для централизации отчётов
- Active scan ZAP
- Dependabot, branch protection

### 10. Заключение
- Критерии Netology — таблица «выполнено / да»

### Приложения
- ZIP `evidence/` или ссылка на GitHub
- Ключевые фрагменты `.yml`
